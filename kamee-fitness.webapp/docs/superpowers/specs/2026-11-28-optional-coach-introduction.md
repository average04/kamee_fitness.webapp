# Optional coach introduction video

The owner asked to implement optional coach introduction video after creating a fictional sample. Existing storage, approved-coach upload/finalization, intro assignment/removal, signed playback and mobile public-profile player already exist. Reuse that pipeline; no new native module, native uploader, database/schema/authorization change or approval requirement.

Add an inline Introduction video section after web Profile details. Clearly label it Optional. Approved coaches can preview the current introduction, upload through the shared existing uploader, preview owned ready choices and explicitly use a selected video. Replacing keeps the previous intro until the server succeeds. Removing detaches only; it does not retire/delete a library asset. Keep mutation controls locked while a change is pending, preserve prior selection on failure, and reset the player instance on selection change. Other coach lifecycle states get honest informational copy, without blocked profile completion. Keep regular library use, pause/resume/cancel, upload guards and profile autosave independent and intact.

Bind intro changes to the owner who rendered the editor using a small request-scoped authenticated Server Action, retaining the existing database RPC and approval policy. It must compare the verified account to expected owner before any mutation; this also protects null/detach after an account switch. Client auth-boundary retirement and per-upload identities prevent stale async work from restoring private state or interfering with a later upload. No service client is used.

Display no introduction section to members when none is selected; retain current app tap-to-play behavior and signed/account-scoped playback. Current technical rules remain MP4/H.264, optional AAC,50MiB effective maximum,10minutes; recommend a short introduction without creating a new hard limit.

Inline reuse is preferred to a new authoring route because leaving the existing profile form can interrupt autosave. The shared uploader may receive a narrow introduction mode; do not duplicate TUS/finalization/security code. No fictional sample is attached to a real coach automatically, and no cleaned fixture accounts are recreated. Preview is the deployment scope; Production and Android fleet stay unchanged unless an actual mobile source change is needed.
